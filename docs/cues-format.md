# 镜头表格式（cues.md）

镜头表决定视频里每一页「哪句话说到时，画面做什么」：卡片出现、数字强调、示意图部件逐个出现，在论文原图上框选、聚光、推镜头。

- **谁写、谁审**：Claude 写，ChatGPT 对照预览审核；素材和镜头表都做完才算审完（用户 2026-10-07 同意的方案，见 [docs/proposals/visual-v2.md](proposals/visual-v2.md)）。
- **放在哪**：本期文件夹里的 `cues.md`。没有这个文件也能合成，每页一开始就完整显示所有内容，只有翻页动画。
- **示例**：[episodes/example/cues.md](../episodes/example/cues.md)，每种动作都用了一次；方案的附录有第二期三页的完整写法。

## 写法

每页一节，先写素材，再写动作表：

```markdown
## 第 8 页

- 原图：figures/table1.png（3254×684，校验 5d41402a）
- 始终可读：表头（基准、指标名和↑↓） | 7%, 0%, 100%, 43%；Method 列 | 50%, 12%, 9.5%, 45%

| 从哪句 | 到哪句 | 动作 | 目标 | 位置 | 说明 |
|---|---|---|---|---|---|
| 直接生成的失败率是 | | 框 | 原图 | 51.2%, 56.9%, 4.7%, 8% | 80.00 |
```

- **`## 第 N 页`**：页码和讲稿一致。没有动作的页不用写。第一页之前可以写标题和说明，程序不读。
- **`- 原图：`**：用到框、聚光、镜头的页必须写，格式是「文件（宽×高，校验 8 位校验码）」。尺寸和校验码先空着（写成「校验 由 npm run check 给出」），运行 `npm run check` 会给出。原图重截过（同尺寸也算），检查就会报错：先用预览重新核对这一页的位置，再更新尺寸和校验码，不能只改数字。原图要用 PNG（`npm run figure` 截的就是），或写了宽高的 SVG。
- **`- 示意图：`**：用到示意图部件（`#id`）的页必须写，格式是「diagrams/page<页码>.svg（部件：id1、id2）」，列出的部件必须在 SVG 里。只要用到部件，SVG 里的 id 就不能重复（不写这一行也照样检查）：重复了，页面只找得到其中一个，另一个该隐藏时也不会隐藏。
- **`- 始终可读：`**：理解这张图必需的区域（坐标轴、图例、单位、行列标题、指标方向），写成「名字 | 上, 左, 宽, 高」，几项用「；」隔开。聚光时这些区域不压暗；镜头装不下它们时，预览会列出来，要由卡片或图下说明交代。
- **动作表**：6 格都要有，空着的格子也要留着。说明一栏写给审稿人看，比如框里是哪个数字、为什么这样取景。

## 用句子定位

- 「一句」就是讲稿里本页「旁白」的一行，和字幕的一行对应。
- 「从哪句」「到哪句」写那一行的**开头几个字**，必须恰好是本页唯一一行的开头。拿来比的是发音替换之前的原文，空格不算，写在表里的末尾标点也不算。
- 只比开头，所以「提供记忆后」不会撞上「不提供记忆时」；两句开头相同（比如都以「假如」开头）时多写几个字。
- 「到哪句」不能早于「从哪句」。

## 动作

每句的时间取自实际配音：从这句开口算起，到下一句开口为止；本页最后一句到本页结束。

| 动作 | 目标 | 怎么动 | 持续到 |
|---|---|---|---|
| 出现 | `卡片N` 或 `#部件id`；`、` 隔开的依次出现（每隔 0.3 秒），`+` 连起来的同时出现 | 开口时淡入约 0.5 秒；示意图里的线条（`line`）像笔一样画出来，箭头最后出现；虚线（写了 `stroke-dasharray`）保持虚线，跟着部件淡入 | 本页结束（不写「到哪句」） |
| 强调 | `卡片N「文字」` | 开口后 0.3 秒，文字放大、变色约 1.1 秒 | 自动恢复（不写「到哪句」） |
| 框 | `原图`，写位置 | 开口时淡入 0.35 秒 | 「到哪句」结束（不写就是本句结束）后淡出 0.3 秒；到最后一句的随翻页淡出 |
| 聚光 | `原图`，写位置 | 开口时压暗其余部分 0.4 秒（浅色风格是冲淡） | 同上，恢复 0.4 秒 |
| 镜头 | `原图`，写要放大到的范围 | 开口时推近 0.9 秒，范围整个装进画面，放大后原图边缘不露空白 | 同上，拉回全图 0.9 秒 |

- **卡片N**：本页「要点」「步骤」或「指标」的第 N 条，按讲稿里的顺序数；`comparison` 页先数基线要点，再数本文要点。
- **被「出现」的目标**在本页开始时隐藏；没写「出现」的卡片和部件一直可见。部件出现的先后完全按镜头表，不按 SVG 里的顺序。
- **限定说明**（「示意图」「假设」、限制条件）和它说明的部件同时出现：用 `+` 连起来，或者写成同一句开头的两行；也可以不写「出现」，让它一直可见。`、` 的逐个出现只用于各自看得懂的目标。
- **强调的文字**必须在这张卡片的同一段里恰好出现一次，也不能是更长数字的一部分（`80` 不算 `80.0` 里的）。强调是句级提示：在这句开口后亮一下，不保证正好落在念到那个数字的瞬间。强调只用在我们自己的卡片上，不改原图。
- **位置**沿用红框的写法「上, 左, 宽, 高」，都是相对**原图文件**的百分比（包括图四周的白边）；4 个数都要带 %，宽、高大于 0，左 + 宽、上 + 高不超过 100%。

## 组合和冲突

- 镜头、聚光、框可以同时有，比如推近后在聚光的一列里再框一个数字；框和聚光跟着镜头一起移动、放大，线条粗细不变。
- 冲突按动作的**完整时段**算（进场、停留、退场或拉回都算）。下列情况报错：
  - 同一时间有两个镜头，或两个聚光（前一个还在拉回、后一个已经开始也算）；
  - 同一个目标出现两次，或者强调一张还没出现的卡片；
  - 没有原图的页写了框、聚光、镜头；
  - 镜头没在本页最后 1 秒之前拉回全图；出现、强调没在翻页淡出（最后 0.35 秒）之前做完；框、聚光、镜头没在翻页淡出之前进完场，或者退场没在那之前做完（持续到最后一句的框和聚光随翻页淡出，但也要先进完场）；
  - 时间不够：比如几个目标依次出现，最后一个来不及在翻页前出现。程序不会悄悄拉长页面、截断动作或把动作带到下一页，要调整镜头表。
- 同一时间超过 3 个框只给提醒。
- 时间的检查要用实际配音，在 `npm run preview` 和 `npm run render` 时做；`npm run check` 只查格式、句子、目标、位置和原图。

## 不能误导

- 只叠加，不改原图：不缩放柱高、不给数据改色、不做数字滚动。
- 框只框旁白此刻说的内容；多框进去的东西要在说明里讲清是什么。
- 镜头的边缘落在空白处，不切出半截字（用 `npm run figure ... --gaps` 找空白行、空白列）。
- 示意图的箭头只表示论文写明的关系。

## 检查和预览

1. `npm run check -- <本期文件夹>`：检查镜头表的格式、句子、目标、位置、原图尺寸和校验码；上次的配音还和稿子一致时，也按它查时间；预览过期或还没做时提醒，预览是最新的会明确说「预览是最新的」。
2. `npm run preview -- <本期文件夹> [页码]`：用实际配音的时间，给每个动作截「之前、进场中、稳定、之后」四张，加上翻页、页末和几个动作重叠的时刻，生成 `output/preview/index.html`。每张图旁边写着时刻、那一句旁白、动作和位置；镜头还写出放大后看到的范围和窗口外的始终可读区。缩图是手机上的大小（640×360）。
3. 加 `--clip` 和页码，把这一页做成带声音的短片 `output/preview/page<页码>.mp4`，看节奏是不是太挤。
4. 预览记下了它依赖的全部输入：讲稿、镜头表、原图（同尺寸重截也算）、示意图、页面的实际内容（版式映射后的文字、卡片和镜头动作）、模板和风格文件、全部代码和锁定的依赖版本、所选风格、配音的声音、语速和时间、实际用来画字的字体（包括回退字体）、浏览器版本。任何一项变了，预览就过期，不能拿来审核；重新运行 `npm run preview`。
5. `index.html` 只是生成时的快照，打开它不会重新检查。审核前先运行 `npm run check`，看到「预览是最新的」再用它核对；配音时间、字体和浏览器要到 `npm run preview` 或 `npm run render` 时才查得到，它们发现过期也会提醒。静帧只能看画面，声音由用户听。
