# 本地自动制作与交接

输入选定的 arXiv 论文链接，程序依次启动 Codex 和 Claude Code，保存每轮交接，检查、返修、复审并合成。最后由你看成片、听声音、确认并手动上传。现有手动流程仍可使用。

验证状态（2026-10-13）：159 项测试通过；第五期真实预览验证了绝对时间/行号变化的按页复用（T101、T102），真实 PDF 分页读取和 Edge 预览基础验证见 T94。真实连接测试（T95）中 Codex 带图调用通过；Claude Code 当时被本机环境变量指向 DeepSeek，读不了图（T104），用户删掉这些设置、改用 Claude 订阅登录后（T107），T109 用生产程序的参数补测了一次：Claude 正确读出图片内容，结构化结果通过。一篇新论文的完整制作尚未验证。

## 开始

电脑需要 Node.js 20 以上、项目依赖、Microsoft Edge，以及已经安装并登录的 Codex CLI 和 Claude Code。沿用两边各自的模型配置和认证，不需要在本程序里填 API key。模型调用会使用相应账号额度；程序不自动切换付费 API。

Claude Code 用你自己的 Claude 订阅登录（`claude auth login --claudeai`），连 Anthropic 官方接口（用户 2026-10-13 决定，T111）。如果环境变量把它指向别的接口、设了 API 凭据、走云服务商，或指定的不是 Claude 官方模型名（比如之前的 DeepSeek），开始和恢复任务前就会停下：不建论文目录、不调用模型，并说明是哪个变量（不显示变量的值）。删掉或改正后重开终端再试。

先检查工具能否启动，以及 Claude Code 的登录方式和接口（不请求模型、不验证额度；Codex 的登录请自行确认）：

```powershell
npm run produce -- doctor
```

先看看流程（不下载、不调用模型、不创建文件）：

```powershell
npm run produce -- https://arxiv.org/abs/2610.07967v1 --dry-run
```

开始制作**尚未开工的新论文**：

```powershell
npm run produce -- https://arxiv.org/abs/<论文编号和版本> --minutes 5 --audience 科普向
```

把 `<论文编号和版本>` 换成真实编号。也接受纯编号、arXiv 的 PDF 或 HTML 链接。不写版本则下载最新版本，之后把版本锁定。首版不接其他网站，也不接管已有手动稿件或已发布视频，避免覆盖。选题、许可和素材可用性仍以实际论文为准。

运行时电脑需要开着、能联网。程序一次处理一篇；终端可以放在后台。正常流程无需在两个聊天窗口之间转发提示词。遇到不能确定的事实、许可、素材问题或工具故障，任务会停止并保存原因。

## 自动步骤

1. 复用开工脚本，核对论文身份、下载指定版本 PDF，填好稿件开头；用已有的 Edge/pdf.js 方式准备分页文本和全部原页图片（`output/paper/`），不要求 CLI 另装 Python/PDF 阅读工具。提取错序时以原页为准。
2. Codex 读论文，写 `script.md`、原文核对表和 `materials.md`。
3. 启动独立 Codex 会话，逐条核对原文；有问题由另一次写稿会话修订，再独立复审。
4. Claude 按素材清单截原图、画 SVG、写 `cues.md`。
5. 程序检查稿件，生成全片预览；再检查全部页的输入、实际字体/浏览器和配音时间。没有镜头动作的页也要有预览。
6. Codex 按页、分批审核所有预览关键时刻。每个时刻同时提供 640×360 手机图和原尺寸；每批最多 6 个时刻、12 张图，必须返回实际审核的页码和图片清单。程序检查覆盖情况。
7. 一轮图片批次全部审完，汇总问题后再交 Claude 返修；逐批报告只存本地，每轮只写一条 WORKLOG。重做完整预览后，复审未通过或实际预览变了的页，未变且已通过的页保留审核；中断后可接着审剩余批次。稿件或素材说明改变时重新独立查原文；共享说明、来源表、模板、字体或浏览器等共同输入变化时全页复审。
8. 通过后合成本地视频、字幕、章节、封面；Claude 检查画面和时间轴、实际看抽帧，列用户试听点。
9. 交你看成片、听声音、最终确认、手动上传。发布记录仍在你给出链接后由 Claude 维护。

没有自动 commit、push 或上传步骤。程序核对文件和证据覆盖，内容是否准确、图片是否可读仍依靠模型审核，最终由用户把关。审核报告里的“实际查看”是 agent 的声明；图片输入和逐图覆盖能减少漏审，不能替代人工保证。

## 进度、停止与恢复

```powershell
npm run produce -- list
npm run produce -- status <任务编号>
npm run produce -- stop <任务编号>
npm run produce -- resume <任务编号>
```

也可在运行终端按 Ctrl+C。程序终止自己启动的子进程树、保留进度、释放锁。超时和调用失败保留日志；恢复从未完成阶段继续，先重新检查审核输入。

如果显示 `needs_user`，恢复时要写明决定，不能直接跳过审核：

```powershell
npm run produce -- resume <任务编号> --feedback "已确认许可；请按原文允许的范围继续"
```

默认整项任务最多返修 3 轮、调用模型 100 次，每次模型/制作步骤最多 20 分钟。每个图片批次算一次调用，失败的调用也算；这些限制控制工作量，不代表货币预算。上限可在启动时调整，或者明确说明决定后恢复：

每轮开始前按剩余图片批次数检查调用预算，并在任务状态的 `callEstimate` 保存本轮批次和建议总上限；不足以完成整轮时先停下来，不自动提高上限。建议值按剩余返修轮数估算，是规划值，不能保证覆盖所有原文返修或工具重试。图片审核的正常淡入、进场等截图会附时刻说明，返回结果可用 `notes` 提不阻断的建议。

逐页审核指纹使用真实页面和本页镜头内容，去掉来源 `lineNo` 后重算；动作名称和时刻标签里的来源行号换成本页动作序号，截图的成片绝对 `videoTime` 不参与。前页单纯变长或镜头表前面加减行，不使后面未变的页重审。图片、本页时间/动作/限定说明与字体/浏览器等仍参与核对。预览记录保留原始行号和成片时间供定位；素材清单/原文核对表的实际内容变动仍保守地触发全页复审。

```powershell
npm run produce -- resume <任务编号> --max-calls 150 --max-revisions 5 --feedback "已检查返修记录，同意继续"
```

格式/镜头表检查问题才交素材返修。网络、配音、下载、浏览器、超时及其他无法分类的故障会暂停，不消耗返修轮数；失败的模型请求仍计入调用次数。合成前检测到浏览器或字体使预览过期，会先重做预览并复审，不一直停在合成阶段。

审核期间本期输入变了，必须重新审核；本期以外全部 Git 已跟踪和未忽略文件（WORKLOG 单独保护）、其他期的 `figures/` 原图（即使忽略）、`.claude/`、`.codex/`（即使忽略）、Git HEAD/当前分支/packed-refs/远端引用变化时停止，程序不恢复/覆盖它们。Git 清单读取失败也停止，不缩小检查范围。确认这些改动后，可显式更新基准，重新进入原文和视觉审核：

```powershell
npm run produce -- resume <任务编号> --refresh-inputs --feedback "已确认共享修改来源，同意以当前文件重新审核"
```

整个项目同时只有一项自动制作任务，包含 WORKLOG 写入锁。普通 Claude/Codex 聊天不会自动遵守这把锁；运行期间避免让其他会话修改相同文件。进程意外崩溃后，只在锁的所有进程均退出时自动回收锁；有遗留子进程会拒绝继续，先结束原任务的子进程。

## 文件

成片仍在 `episodes/<日期>-<论文编号>/output/video.mp4`，旁边有封面、字幕、章节、预览和检查抽帧。

每轮交接保存在本地 `.production/jobs/<任务编号>/`：

- `state.json`：阶段、返修次数、调用次数、审核输入指纹及任务编号。
- `NNN-阶段-to-codex.md` / `to-claude.md`：完整交接提示词。
- `NNN-阶段-result.json`：通过、需返修或需你决定，以及核对依据。
- `NNN-阶段-handoff.md`：可直接阅读的结果和下一步。
- `.log`：该次模型或制作命令输出，用于查错误。

以上文件和 `.production-owner.json` 都忽略提交；不保存登录配置或主动输出密钥，但日志可能含论文内容与本地路径，不应公开。程序统一按 AGENTS 第4节追加 WORKLOG，维护本自动任务及最终用户审核的待办行；agent 不直接写全局记录。

## 工具路径与权限

默认在 PATH 和常见 Windows 安装位置找工具。找不到时，将 `DAILYPAPER_CODEX_BIN`、`DAILYPAPER_CLAUDE_BIN` 设置为实际 `.exe` 或 `.js` 绝对路径；不要填写 `.cmd`、`.ps1` 或一串命令。程序用参数数组和标准输入启动工具，不把论文链接/提示词拼成 shell 命令。

Codex 写稿用 `workspace-write`，原文/图片审核用 `read-only`；Claude 用 `dontAsk` 和限定工具，未获授权的工具拒绝执行。没有使用跳过所有权限/沙箱的参数。CLI 会沿用各自本机配置、规则、插件和认证；权限不足会停止。

这不是操作系统级隔离环境。Claude 允许的 Node/Python 工具可访问工作区之外，本机插件和配置也可能执行行为；制作范围靠明确指令、CLI 权限以及改动检查共同约束。共享文件一旦被意外改动，程序停止并保留现场，不擅自回滚。需要更强的隔离时再接独立容器或专用账号。

官方接口说明：[Codex 非交互模式](https://learn.chatgpt.com/docs/non-interactive-mode)、[Claude Code 程序调用](https://code.claude.com/docs/en/headless)。
