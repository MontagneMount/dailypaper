## 二、风格

## 三、哪些动画自动做，哪些要写进镜头表

- **自动做的只有翻页**：每页开头淡入约 0.6 秒，结尾淡出约 0.35 秒。不需要镜头表，也不改变任何内容。
- **其余的内容动画都要写进镜头表、经过审核**：卡片出现、数字强调、示意图部件出现、框、聚光、镜头。程序不会自己猜时机，也不会「对不上就平均分配」。原因：靠关键词猜很容易对错，比如「提供记忆」会撞上「不提供记忆」，「80」和「80.0」写法不同，同一个数字也可能属于不同的指标。
- **没有镜头表的页，内容完整静态显示**：所有卡片和示意图部件从一开始就都在，不隐藏、不猜顺序，只有翻页动画。
- 以后可以加一个命令，自动生成镜头表的**草稿**（`cues.draft.md`，不参与合成），审核改好后再改名成 `cues.md` 才生效。这不在第一步里。

## 四、镜头表 `cues.md` 怎么写

每期一个文件，放在本期文件夹里，由 Claude 写、ChatGPT 审。按页分节，每页先写素材信息，再写动作表：

```markdown
## 第 8 页

- 原图：figures/table1.png（3254×684，校验 5d41402a）
- 始终可读：表头（基准、指标名和↑↓） | 7%, 0%, 100%, 43%；Method 列 | 50%, 12%, 9.5%, 45%

| 从哪句 | 到哪句 | 动作 | 目标 | 位置 | 说明 |
|---|---|---|---|---|---|
| 直接生成的失败率是 | | 框 | 原图 | 51.2%, 56.9%, 4.7%, 8% | 80.00 |
```

完整示例见文末附录（第二期第 3、5、8 页）。

### 1. 用句子定位

- 「一句」就是讲稿里本页「旁白」的一行，和字幕的一行一一对应。
- 拿来比对的是**发音替换之前**的旁白原文。比对前去掉所有空格；写在表里的句子末尾的标点也去掉。
- 「从哪句」「到哪句」都写那一行的**开头几个字**，必须恰好是本页**唯一一行**的开头：
  - 找不到 → 报错；
  - 有两行以上都以它开头 → 报错（不会取第一个）。例如第二期第 5 页有两句以「假如」开头，就要写「假如最看重」或「假如要比较」。
- 只比对句子开头，所以「提供记忆后」不会撞上「不提供记忆时」。
- 「到哪句」必须在本页，而且不能早于「从哪句」。

### 2. 动作、目标和持续时间

每一句的时间取自实际配音（narration.json）：从这句开口算起，到下一句开口为止；本页最后一句到本页结束为止。

| 动作 | 目标 | 进场 | 持续到 | 退场 |
|---|---|---|---|---|
| 出现 | `卡片N`，或示意图部件 `#id`；一行可以写几个：用「、」隔开的按顺序每隔 0.3 秒出现一个，用「+」连起来的同时出现 | 从哪句开口时淡入，约 0.5 秒；箭头像笔一样画出来 | 本页结束（「到哪句」不能写） | 随翻页淡出 |
| 强调 | `卡片N「文字」`，文字必须在这张卡片里恰好出现一次 | 从哪句开口后约 0.3 秒，放大、变色约 1.1 秒 | 一次性提示（「到哪句」不能写） | 自动恢复 |
| 框 | `原图`，带位置 | 从哪句开口时淡入，约 0.35 秒 | 到哪句结束（不写就是本句结束） | 淡出约 0.3 秒 |
| 聚光 | `原图`，带位置 | 从哪句开口时压暗其他部分，约 0.4 秒 | 同上 | 恢复约 0.4 秒 |
| 镜头 | `原图`，带位置（要放大到的范围） | 从哪句开口时推近，约 0.9 秒 | 同上 | 拉回全图，约 0.9 秒 |

- `卡片N` 是本页「要点」或「步骤」的第 N 条，按讲稿里的顺序数，所以稿子不变它就不变。
- 强调是**句级**提示：在这句开口后亮一下，不保证正好落在念出那个数字的瞬间（逐词对齐是 T12，不在这一步）。
- 强调只用在我们自己的文字上（卡片），不放大、不改色论文原图里的任何数据。
- 被「出现」的目标在本页开始时隐藏；没被「出现」的卡片和部件**一直可见**。示意图部件出现的先后完全按镜头表，不按 SVG 文件里的顺序。
- 限定说明（「示意图」「假设」、限制条件）必须和它说明的部件**同时**出现：用「+」连起来，或者写成同一句开头的两行。「、」的逐个出现只用于各自能单独看懂的目标。

### 3. 组合与冲突

- 允许同时有镜头、聚光和框，比如推近后在聚光的一列里再框一个数字。框和聚光跟着镜头一起移动和放大。
- 冲突按动作的**完整时段**算：进场、停留、退场或拉回都算在内。例如相邻两个镜头，前一个还在拉回、后一个已经开始推近，也算冲突。
- 下列情况报错：
  - 同一时间有两个镜头，或两个聚光；
  - 同一个目标「出现」了两次，或「强调」一张还没出现的卡片；
  - 没有原图的页写了框、聚光或镜头；
  - 镜头要在本页最后 1 秒之前拉回全图（拉回过程要完整可见）；「出现」要在翻页淡出之前完成进场；
  - 本页剩下的时间不够把动作做完：比如强调有 0.3 秒延迟和约 1.1 秒动画，一行多个目标还要加上间隔。这时直接报错，让 Claude 调整镜头表，不会悄悄拉长页面、截断动作或把动作带到下一页。
- 同一时间超过 3 个框只给提醒。

### 4. 位置和坐标

- 沿用 figure_annotated 红框的写法「上, 左, 宽, 高」，都是相对**实际图片文件**的百分比，包括图片四周的白边。
- 每个数都必须是有限数字；宽、高大于 0；上、左不小于 0；**左 + 宽**和**上 + 高**都不超过 100%。
- 镜头只等比放大（不变形），框和聚光跟着同一个变换走。
- 每页写明所用原图的文件名、像素尺寸和校验码（`npm run check` 会给出）。检查时任何一项对不上就报错：原图重截过（同尺寸重截也算），必须重新看预览、核对这一页的位置，再更新尺寸和校验码，不能只改数字绕过复核。
- 截图的白边按分辨率等比留，同一张图换分辨率后，百分比位置不变。

## 五、防止误导的规矩

- **只叠加，不改原图**：框、聚光、镜头都是叠在原图上的；不缩放柱高、不给数据改色，不制造「数据变了」的印象。
- **不做数字滚动**：比如 96% 滚到 77.3%，滚动中会出现原文里没有的中间数字。
- **始终可读区**：每页可以列出理解这张图必需的信息，比如坐标轴起点和刻度、图例、单位、行列标题、基线、指标方向（↑↓）。
  - 聚光时这些区域**不压暗**，过渡帧里也一样。
  - 镜头取景如果装不下它们，镜头期间必须由画面上一直可见的卡片或图下说明交代，在「说明」里写明在哪。preview 索引会列出每个镜头窗口外的始终可读区，方便核对。
  - 第二期第 3 页的柱状图纵轴从 60% 开始，所以那一页只用聚光不推镜头，而且纵轴、图例列为始终可读区。
- **框只框旁白此刻说的内容**：多框进去的东西要在「说明」里讲清是什么。比如第二期第 8 页，正式版只框 53.50，不连带 (-26.50)。
- **限定说明不能晚出现**：「示意图」「假设场景」这类标签和它说明的部件放在同一组里一起出现，或者从一开始就可见。限制条件要和对应的阶段一起出现，比如「这一阶段不输入当前问题」要和记忆卡同时出现，而不是最后才补。
- **示意图的箭头只表示论文写明的关系**，不暗示论文没给出的因果。
- **镜头边缘落在空白处**，不切出半截字。

## 六、检查、预览和验收

### `npm run check` 增加的检查

- 镜头表：页码存在；句子能唯一找到；起止顺序正确；动作和目标类型匹配；卡片序号、卡片里的文字、示意图 id 都存在（示意图 id 也不能重复）；位置合法（见第四节第 4 条）；原图尺寸和表里一致；第四节第 3 条的冲突。
- 回归测试至少包括：否定开头（「不提供记忆时」和「提供记忆后」）、两句开头相同、数字写法不同（80 / 80.0）、左 + 宽超过 100% 这类组合越界。

### `npm run preview -- <本期文件夹> [页码]`

- 和正式合成**共用**同一套时间轴、风格、素材和动作代码，时间以**当前实际配音**为准：先补齐缺的或改过的配音（有缓存，很快），再截图。
- 每个动作截四张：动作前、进场过渡中、稳定后、退场或拉回之后。另外截每页开头和结尾的翻页边界，以及几个动作重叠的时刻。
- 生成 `output/preview/index.html`，每张图旁边写明：
  - 页码、时刻、完整的句子原文；
  - 动作、目标文件或 id、位置；
  - 每个镜头窗口外的始终可读区；
  - 一张手机尺寸（640×360）的缩图，用来检查手机上看不看得清。
- 加 `--clip` 把单独一页合成成带声音的短片，检查节奏，比如短页上动作是否太挤。
- 索引里记下所有影响画面的输入的指纹：稿件、配音、原图（同尺寸重截也算）、镜头表、示意图 SVG、风格文件和模板、字体和渲染参数、动作代码的版本。每次打开索引、运行 `npm run check` 或验收时都和当前输入比对，任何一项变了，旧预览就标为「已过期」，不能拿来验收。估算时间做的预览也不能当正式核验。
- 本页第一个动作的「动作前」用页首的初始画面；「出现」的「之后」就是保持到页末的状态。
- 静帧只能检查画面，声音仍然由用户听。

### 合成后的验收

- 「静止时复用画面」不能改变时长：每页和整片的时长、音频、字幕、章节都和不复用时一致（自动测试按帧核对）。每页最后一帧是所有动作的终态，最后一句字幕不丢。
- `--static`：所有内容一开始就完整显示，用所选风格，不需要镜头表，结果和现在的静态视频一样。
- 没有镜头表的旧稿照样能合成（完整静态内容 + 翻页）。
- **保护已发布的期**：`episodes/published.json` 里已发布的期，`npm run render` 默认拒绝覆盖它的成片，必须显式加 `--force`。

### 风格验收

- 两套风格都要过一遍：六种版式加宽图版、视频封面页、B 站封面、SVG 示意图。
- 字体能否加载、缺字体时的回退要检查。
- 字幕和背景、高亮框和白底原图的对比度要够（文字 4.5:1，框线 3:1）。
- 手机尺寸下字幕、卡片、原图关键数字要看得清。
- 576 dpi 只保证放大后不糊，不代表画面里的字够大，字号仍然要看预览。
- `--gaps` 只是辅助：像 Table 2 那样两组数据之间没有空白行的表格，边界仍要人工逐行核对。

## 七、合成速度

- 样片里每截一帧约 84 毫秒；如果每秒 30 帧全都截，一期 5 分钟要约 13 分钟。
- 改成只在画面变化时逐帧截图，静止时一张图撑到下一次变化（沿用现在的 ffconcat 写法），背景不做持续漂移。估计一期 3～5 分钟，实现后记录实测。

## 八、流程和分工

1. ③ ChatGPT 写稿（不变）。
2. ⑤ Claude 做素材：截原图、画示意图（部件分组、带 id、用风格颜色类，规则写进 `templates/README.md`），写 `cues.md`，跑 `npm run check` 和 `npm run preview` 自查。
3. ④ ChatGPT 审稿时一并审素材和镜头表，对照 preview 索引。**素材和镜头表都做完之后才能算审完**，不能在素材没做好时提前通过。
4. ⑥ 合成，⑦ Claude 查成片画面和时间轴，用户听声音并最终确认。

示例 `episodes/example` 换成新风格，并带一个小的 `cues.md` 作示范。

## 九、不在这一步（第二步再做）

数据动画（按原文数据重画的动态图表，标明重绘）、关键结论大字动画、章节标题卡、片头片尾、配乐和音效、字幕逐词高亮（T12）、自动生成镜头表草稿。

## 十、实现顺序（复审通过、用户同意后）

1. 风格：模板改用风格变量，做浅色学术和深色两套；封面一起改，给用户看预览。

3. 镜头表：解析和检查，出现、强调、框、聚光（带始终可读区）、镜头；`npm run preview` 和索引；`npm run figure` 576 dpi 和 `--gaps`。
4. 文档和测试补齐，交 ChatGPT 审代码；第三期起用新流程。
